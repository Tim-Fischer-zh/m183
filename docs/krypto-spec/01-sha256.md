# Mathe-Spec 01 — SHA-256

Quelle/Norm: **FIPS 180-4** (Secure Hash Standard). Diese Spec beschreibt die Mathematik und den Ablauf. Den C#-Code schreibst du selbst.

SHA-256 nimmt eine beliebig lange Byte-Eingabe und liefert einen **32-Byte-Hash** (256 Bit).

---

## 1. Notation und Grundregeln

- Es wird in **32-Bit-Wörtern** gerechnet (unsigned, in C#: `uint`).
- **Jede Addition ist modulo 2^32** (also normaler `uint`-Überlauf, in C# „unchecked").
- Bit-Operationen: `AND`, `OR`, `XOR`, `NOT`.
- `SHR(x, n)` = logischer Rechts-Shift um n Bit (oben Nullen rein).
- `ROTR(x, n)` = Rotation nach rechts um n Bit. Definition:
  `ROTR(x, n) = (x SHR n) OR (x SHL (32 - n))` — als 32-Bit-Resultat.
- **Byte-Reihenfolge: big-endian** (das höchstwertige Byte zuerst), sowohl beim Einlesen der Wörter als auch beim Ausgeben des Hashes.

---

## 2. Konstanten

### 2.1 Initiale Hash-Werte H[0..7]
Herkunft: die ersten 32 Nachkomma-Bits der **Quadratwurzeln der ersten 8 Primzahlen** (2, 3, 5, 7, 11, 13, 17, 19).

```
H0 = 6a09e667   H1 = bb67ae85   H2 = 3c6ef372   H3 = a54ff53a
H4 = 510e527f   H5 = 9b05688c   H6 = 1f83d9ab   H7 = 5be0cd19
```

### 2.2 Rundenkonstanten K[0..63]
Herkunft: die ersten 32 Nachkomma-Bits der **Kubikwurzeln der ersten 64 Primzahlen**.

Die ersten vier zur Kontrolle:
```
K0 = 428a2f98   K1 = 71374491   K2 = b5c0fbcf   K3 = e9b5dba5
```

Die **vollständige Tabelle der 64 Werte** tippst du aus **FIPS 180-4, Abschnitt 4.2.2** ab (das ist gleichzeitig deine Validierung gegen die offizielle Quelle). Wenn du magst, kannst du sie auch selbst berechnen: K[i] = floor( frac(cbrt(p_i)) * 2^32 ), wobei p_i die i-te Primzahl ist.

---

## 3. Hilfsfunktionen (auf 32-Bit-Wörtern)

```
Ch(x, y, z)  = (x AND y) XOR ((NOT x) AND z)
Maj(x, y, z) = (x AND y) XOR (x AND z) XOR (y AND z)

BigSigma0(x) = ROTR(x,2)  XOR ROTR(x,13) XOR ROTR(x,22)
BigSigma1(x) = ROTR(x,6)  XOR ROTR(x,11) XOR ROTR(x,25)

SmallSigma0(x) = ROTR(x,7)  XOR ROTR(x,18) XOR SHR(x,3)
SmallSigma1(x) = ROTR(x,17) XOR ROTR(x,19) XOR SHR(x,10)
```

Merkhilfe: die **grossen** Sigmas (Σ) nutzen nur Rotationen, die **kleinen** Sigmas (σ) nutzen am Schluss einen Shift.

---

## 4. Padding (Vorverarbeitung)

Ziel: die Nachricht auf ein Vielfaches von **512 Bit (64 Byte)** bringen.

Sei `L` die Länge der Originalnachricht in **Bits**. In Byte-Schritten gedacht:

1. Hänge **ein Byte `0x80`** an (das ist das eine `1`-Bit gefolgt von sieben `0`-Bits).
2. Hänge so viele **`0x00`-Bytes** an, bis die Gesamtlänge **≡ 56 (mod 64)** Byte ist.
3. Hänge `L` als **64-Bit big-endian** Zahl an (8 Byte). Jetzt ist die Länge ein Vielfaches von 64 Byte.

Edge-Case beachten: Bei der leeren Eingabe entsteht genau ein 64-Byte-Block. Bei Nachrichten, die schon nahe an der 64er-Grenze liegen, entstehen zwei Blöcke.

---

## 5. Verarbeitung pro 512-Bit-Block

Initialisiere die acht Arbeitsvariablen mit den aktuellen Hash-Werten:
```
a=H0, b=H1, c=H2, d=H3, e=H4, f=H5, g=H6, h=H7
```

### 5.1 Message Schedule W[0..63]
- `W[0..15]`: die 16 Wörter des aktuellen Blocks, je 4 Byte big-endian eingelesen.
- `W[16..63]`:
  ```
  W[t] = SmallSigma1(W[t-2]) + W[t-7] + SmallSigma0(W[t-15]) + W[t-16]      (mod 2^32)
  ```

### 5.2 Hauptschleife (für t = 0 bis 63)
```
T1 = h + BigSigma1(e) + Ch(e, f, g) + K[t] + W[t]      (mod 2^32)
T2 = BigSigma0(a) + Maj(a, b, c)                        (mod 2^32)

h = g
g = f
f = e
e = d + T1     (mod 2^32)
d = c
c = b
b = a
a = T1 + T2    (mod 2^32)
```

### 5.3 Block-Abschluss
Addiere die Arbeitsvariablen auf die Hash-Werte (alle mod 2^32):
```
H0 += a, H1 += b, H2 += c, H3 += d, H4 += e, H5 += f, H6 += g, H7 += h
```

Dann den nächsten Block verarbeiten (mit denselben, jetzt aktualisierten H-Werten).

---

## 6. Ausgabe

Nach dem letzten Block: gib `H0 || H1 || H2 || H3 || H4 || H5 || H6 || H7` aus, jedes Wort als **4 Byte big-endian**. Ergibt 32 Byte.

## 7. Testvektoren (zum Selbstprüfen)

| Eingabe | Erwarteter SHA-256 (hex) |
|---|---|
| `""` (leer) | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| `"abc"` | `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad` |
| `"abcdbcdecdefdefgefghfghighijhijkijkljklmklmnlmnomnopnopq"` (56 Zeichen, 2 Blöcke) | `248d6a61d20638b8e5c026930c3e6039a33ce45964ff2167f6ecedd419db06c1` |

Zusätzlich: Quervergleich gegen `System.Security.Cryptography.SHA256` mit zufälligen Eingaben (muss immer identisch sein).

---

## 8. Empfohlene Implementierungs-Reihenfolge

1. `ROTR` und `SHR` als kleine Helfer — und mit Hand-Beispielen testen.
2. `Ch`, `Maj`, die vier Sigma-Funktionen — einzeln testen.
3. Big-endian Lesen/Schreiben von `uint` aus/in `byte[]`.
4. Padding — separat testen (Länge des Outputs prüfen: Vielfaches von 64).
5. Message Schedule + Hauptschleife + Block-Abschluss.
6. Testvektoren in dieser Reihenfolge: `"abc"` (1 Block) → `""` (Padding-Edge-Case) → der 2-Block-Vektor.

Stolperfallen: vergessenes big-endian, falsche Rotationsdistanzen, signierte statt unsignierte Shifts, Addition ohne mod-2^32 (in C# `uint` + `unchecked`).

---

## 9. Schnittstelle (du definierst sie, Vorschlag)

Aus dem Design: `IHashFunction` mit `byte[] Hash(ReadOnlySpan<byte> data)`. Intern sinnvoll: ein streaming-fähiger Aufbau (Init / Update / Final) ist eleganter, aber für den Anfang reicht eine Ein-Aufruf-Variante.

Wenn deine drei Testvektoren grün sind, ist SHA-256 fertig — danach kommt **HMAC-SHA256** (kurze Spec, baut direkt darauf auf).
